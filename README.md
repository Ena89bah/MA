# دليل الشركات والمهام

موقع خفيف (HTML/CSS/JS بدون أي بناء) لإدارة:

- **التصنيفات**: الأنشطة والبراندات، وتحت كل تصنيف الشركات/البراندات مع الشعار.
- **الشركة / البراند**: بيانات تواصل متعددة (اسم، رقم، إيميل)، روابط مرجعية، ملاحظات، ملفات وصور.
- **المهام**: نوع المهمة (تواصل مباشر، إرسال إيميل، جلب بيانات التواصل…)، ربطها بشركة، إسنادها لموظف، تحديدها مكتمل/غير مكتمل، تعديلها وحذفها، والفلترة حسب الموظف والحالة والنوع.
- **الموظفين**: إضافة، تعديل الاسم، ترتيب (▲▼)، حذف.
- **البيانات**: تصدير/استيراد نسخة احتياطية JSON وتعديل أنواع المهام.

## قاعدة البيانات

### الوضع الافتراضي (محلي)
بدون أي إعداد تُحفظ البيانات في متصفح كل مستخدم (localStorage). مناسب للتجربة أو لشخص واحد.

### قاعدة بيانات مشتركة (Supabase – مجاني)
لكي يرى جميع الموظفين نفس البيانات:

1. أنشئ مشروعاً على [supabase.com](https://supabase.com).
2. افتح **SQL Editor** والصق محتوى `supabase-setup.sql` ثم **Run** (ينشئ الجدول ومخزن الملفات `files`).
3. من **Project Settings ← API** انسخ `Project URL` و `anon public key`.
4. ضعهما في `config.js`:
   ```js
   window.APP_CONFIG = {
     supabaseUrl: "https://xxxx.supabase.co",
     supabaseAnonKey: "eyJ..."
   };
   ```
5. ارفع التعديل على GitHub.

>
> البيانات تُحفظ كوثيقة واحدة؛ إذا عدّل شخصان في نفس اللحظة فآخر حفظ هو المعتمد. الصفحة تتحدث تلقائياً عند العودة إليها.

## تسجيل الدخول والصلاحيات

نفّذ `supabase-setup.sql` في SQL Editor (ملف واحد لكل الإعداد، ومستثنى من GitHub لأنه يحتوي كلمات السر الأولية). بعدها لا تُقرأ البيانات ولا تُحفظ إلا بجلسة دخول، وكلمات السر مشفّرة في قاعدة البيانات.

- **مدير:** كل شيء، ومنها إدارة الموظفين وكلمات السر.
- **موظف:** يعدّل البيانات، ولا يدير الموظفين.
- **مشاهد فقط:** يقرأ فقط، والحفظ مرفوض من قاعدة البيانات نفسها.
- **الوصول إلى الأقسام:** يخفي التبويبات في الواجهة، لكنه لا يحجب البيانات عن المستخدم المسجل.
- 5 محاولات دخول خاطئة تقفل الحساب 15 دقيقة.
- الجلسة 12 ساعة وتنتهي بإغلاق المتصفح، أو 30 يوماً مع خيار "حفظ تسجيل الدخول".
- مساحة الملفات `files` ما زالت عامة: الرفع والقراءة لا يتطلبان تسجيل دخول.

## البيانات الأولية (مسح نطاق 1 كم)

عند أول فتح للموقع تُحمّل البيانات من `data/seed.json`، وهي مبنية من:

- **دليل المجمع التجاري**: المحلات والمطاعم مع التصنيف والبوابة والشعار والموقع الإلكتروني أو حساب التواصل.
- **OpenStreetMap**: الأنشطة المسماة في نطاق 1 كم (فنادق، سوبرماركت، بنوك، مطاعم…) مع الأرقام والإيميلات المتوفرة. البيانات مرخصة بـ ODbL.
- **خرائط Google**: نتائج مسح يدوي من المتصفح محفوظة في `tools/sources/gmaps-*.json` (الاسم، النوع، الرقم، الموقع). لإضافة منطقة جديدة أضف ملفاً بنفس الشكل ونقطتها في `CENTERS` داخل السكربت.

**منع التكرار:** يُوحَّد كل اسم (الهمزات، التاء المربوطة، التشكيل) وتُحذف الكلمات العامة (متجر، مطعم، فرع…) وأسماء المجمعات، ثم يُقارن الجزء العربي والإنجليزي من كل اسم. أي سجلين يتطابقان يصبحان بطاقة واحدة تجمع كل الأرقام (فرع 1، فرع 2…) والإيميلات وروابط الخرائط. للحالات الخاصة (مثل "كول هان" = "Cole Haan") أضف السطر في القائمة `CANON` داخل السكربت.

المناطق الممسوحة: منطقتان في الخبر و16 مجمعاً في الرياض (`CENTERS`)، والنتائج في `tools/sources/gmaps-area2.json` و `tools/sources/gmaps-riyadh.json`.

كل جهة بدون رقم أو إيميل لها مهمة **جلب بيانات التواصل** مسندة إلى علي.

لإعادة بناء البيانات (Node.js 18+):

```bash
node tools/build-data.mjs
```

نتائج المسح تُحفظ في `tools/.cache/` (غير مرفوعة على GitHub). احذف المجلد لإعادة المسح من المصادر.

> إذا كانت لديك بيانات محفوظة في المتصفح فلن تُستبدل. لعرض البيانات الجديدة استخدم **البيانات ← استيراد JSON** واختر `data/seed.json`.
